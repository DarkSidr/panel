# Входы и подписки

В примерах `example.org` — домен сайта, `panel.example.org` — домен панели.
Подставьте имена, указанные при установке.

## Автоматическая настройка VLESS

После сохранения нового включённого входа синхронизация применяет параметры
в течение 15 секунд. Обновите страницу перед копированием ссылки клиента.

| Транспорт | Защита | Публичный адрес |
|---|---|---|
| RAW/TCP, XHTTP, gRPC | REALITY | Домен сайта, TCP 443 или дополнительный порт |
| WebSocket, HTTPUpgrade | TLS через nginx | Домен панели, TCP 443 |
| XHTTP/gRPC с `[TLS]` в примечании | TLS через nginx | Домен панели, TCP 443 |

Сервис выбирает свободный локальный порт, Listen IP `127.0.0.1`, задаёт External Proxy,
создаёт ключи REALITY при необходимости и публикует маршрут в nginx/firewall.
Уже обработанные входы повторно не перенастраиваются. Клиентов создаёт владелец панели.

`[MANUAL]` в примечании нового входа отключает автонастройку.
Для явной настройки существующего входа:

```sh
python3 /opt/proxy-stack/proxyctl.py configure-inbound 1 --security reality
python3 /opt/proxy-stack/proxyctl.py configure-inbound 1 --security tls
```

TLS через nginx подходит для HTTP-транспортов; RAW/TCP в этой схеме требует REALITY.
VMess/Trojan поддерживаются через HTTP-транспорты с явной настройкой TLS.

Управление автоматизацией:

```sh
python3 /opt/proxy-stack/proxyctl.py auto-setup off
python3 /opt/proxy-stack/proxyctl.py auto-setup on
```

Включение автоматизации сохраняет текущие входы и применяется к будущим новым входам.

## Ручные параметры

Локальный порт каждого входа должен быть уникальным, выше 1024 и не совпадать
с портами служб. Вход слушает `127.0.0.1`; публичный адрес задаётся через External Proxy.

Для REALITY:

- VLESS с RAW/TCP, XHTTP или gRPC.
- Target `127.0.0.1:9443`, `xver=1`, SNI домена сайта.
- Приём PROXY protocol через Sockopt; не включайте его одновременно в двух местах.
- External Proxy: домен сайта, публичный TCP-порт, безопасность `same`.
- Для XHTTP/gRPC flow клиента пустой; XHTTP использует `stream-one`.

Для TLS через nginx:

- WebSocket, HTTPUpgrade, XHTTP или gRPC; локально `security=none`.
- Уникальный path/serviceName из `[A-Za-z0-9_-]`, минимум 8 символов.
- External Proxy: `panel.example.org`, TCP 443, безопасность `tls`.
- XHTTP использует `stream-one`; flow клиента пустой.

Несколько REALITY-входов могут использовать разные публичные порты с одним SNI.
Чтобы использовать TCP 443 с разными SNI, сначала добавьте DNS-запись нового имени,
затем выполните:

```sh
python3 /opt/proxy-stack/proxyctl.py add-reality-name xh.example.org
```

Команда расширит сертификат. Домен панели нельзя использовать как REALITY SNI.

## AmneziaWG

AWG использует отдельный раздел **Hosts**, поскольку у него нет streamSettings.

1. Создайте AWG-вход: userspace, Listen IP `127.0.0.1`, свободный UDP-порт, например `51820`.
2. В **Hosts → Добавить хост** задайте `panel.example.org:443`, безопасность `same`.
3. Привяжите хост к AWG-входу и включите его.
4. Дождитесь синхронизации и обновите подписку либо заново импортируйте профиль клиента.

nginx перенаправляет публичный UDP-порт на локальный порт входа.
Публичный UDP-порт должен быть свободным среди других AWG-хостов.
Используйте клиент с поддержкой AmneziaWG; REALITY к этому протоколу не применяется.

## Подписки и диагностика

Персональная подписка находится в карточке клиента. Включены обычный формат ссылок,
Xray JSON и Clash/Mihomo YAML. Ссылки содержат секрет клиента и не предназначены
для публикации. nginx не кэширует подписки и не пишет их в access log.

В полученном профиле адрес должен быть публичным. `localhost` и внутренний порт
означают неверные настройки External Proxy либо Hosts. После изменения адреса,
порта или безопасности обновите подписку на устройствах.

```sh
python3 /opt/proxy-stack/proxyctl.py sync
python3 /opt/proxy-stack/proxyctl.py doctor
journalctl -u proxy-stack-sync.service -n 30
```

Если активный вход не поддерживается или настроен неверно, синхронизация сохраняет
предыдущую конфигурацию. Исправьте либо отключите ошибочный вход и повторите sync.
