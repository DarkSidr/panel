# Что защищает TLS/REALITY и что остаётся видимым

Автонастройка использует REALITY для новых VLESS RAW/XHTTP/gRPC. WS и HTTPUpgrade
используют TLS на nginx: core REALITY с этими транспортами несовместим.
Trojan можно использовать через поддерживаемый клиентом HTTP-транспорт с TLS;
обычный Trojan/TLS тоже шифруется, но его RAW-вход не обслуживается нашим HTTP-адаптером.
Название протокола и наличие nginx не гарантируют отсутствие блокировок.

| Наблюдатель | Что может видеть |
|---|---|
| Провайдер устройства / наблюдатель на маршруте | IP VPS, порт, время, размеры/объём пакетов, TLS-метаданные, SNI без ECH; DNS-запросы при незашифрованном DNS |
| Интернет-сканер | Доступные порты, публичный сайт и сертификат, ответы на зондирование; может пытаться определить сервисы |
| Администратор / хостер с контролем VPS | Серверную конфигурацию и ключи, метаданные входа/выхода; внутренний HTTP, где нет дополнительного HTTPS до конечного сайта |

При корректном TLS и проверке сертификата провайдер не читает HTTP-пути, заголовки,
пароль панели или содержимое запросов. Это предполагает, что на устройстве не установлен
доверенный перехватывающий TLS-прокси и само устройство не скомпрометировано.
REALITY маскирует TLS-поведение, но не скрывает IP и статистику соединения.
Ни uTLS fingerprint, ни порт 443 не гарантируют неотличимость от браузерного трафика.

nginx сам расшифровывает TLS для HTTP-входов, панели и подписок. При REALITY
nginx stream передаёт соединение без расшифровки в Xray. Loopback backend с
security=none у TLS-профиля — внутренний участок внутри VPS, а не открытый HTTP
из устройства пользователя в интернет. Владение VPS не означает автоматическую
возможность расшифровать дополнительный HTTPS между приложением и конечным сайтом.

Для уменьшения раскрытия:
- Проверять сертификаты; не использовать allowInsecure как постоянное решение.
- Обновлять ядра приложений на устройствах, а не только панель сервера.
- Использовать поддерживаемые сочетания транспорта и защиты, работающий сайт/fallback.
- Сохранять панель и backend на loopback, ограничивать попытки входа, включить 2FA.
- Держать персональные подписки/UUID/пароли и резервные копии приватными.
- Отдельно согласовать DNS и IPv6 на клиентах; смена DNS только на VPS не меняет
  DNS-поведение всех подключаемых приложений.

Ограничение входа в панель/2FA защищает управление сервером, а не маскирует VPN-пакеты.
Разные поддомены одного IP не являются независимым резервом от блокировки IP.
Серверный успешный тест не доказывает проходимость DPI у конкретного оператора.
